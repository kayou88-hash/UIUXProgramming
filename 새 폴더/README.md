# 가상의 게임 THALASSA 사전 예약 페이지

## 사용자와 목표
    -사용자 : 게임 테스트에 참여한 테스터
    -목표 : 테스트 기간을 정하고, 설정한 내용을 확인한다.

## 사용자의 흐름
    1. 캐릭터 정보 수집에 동의하고 '피드백 입력하기'를 누른다.
    2. 캐릭터명을 입력한다. 비어 있으면 같은 단계에서 안내를 받는다.
    3. 테스트 기간을 선택하고 필요하면 질의 응답을 포함한다.
    4. 캐릭터명, 테스트 기간, 질의응답 설정을 확인하고 수정하거나 완료한다.
    5. 설정 완료 안내를 확인하고, 필요하면 다시 설정한다.

## 인터렉션 시나리오
    1. 시작과 녹음 활용 안내
    - 행동, 이벤트: 기존 동의 체크박스를 선택하고 '피드백 입력하기'를 클릭한다.
    - 조건 : 캐릭터 정보 수집 동의가 선택되었는가?
    - 반응, 다음 상태 : 동의 전에는 버튼을 누를 수 없다. 동의 후 클릭하면 사용 목적을 설명하는 안내 팝업이 열린다.
                    팝업에서 '돌아가기'를 누르거나 Esc를 누르면 동의를 해제하고 시작화면에 남는다.
                    '동의하고 작성하기'를 누르면 캐릭터명 입력 화면을 연다.
    2. 캐릭터명 입력
    -행동, 이벤트 : 캐릭터명을 적고 '플레이 시간 선택하기'를 클릭한다.
    -조건: 앞뒤 공백을 지운 제목이 비어 있는가?
    -반응, 다음 상태 : 비어있으면 같은 화면에 오류를 표시하고 입력창에 초점을 둔다.
                    값이 있으면 저장하고 플레이 시간으로 이동한다.
    3. 조건 선택
    -행동, 이벤트 : 플레이 시간을 바꾸나 로그인 횟수를 선택하고 '내용 확인하기'를 클릭힌다.
    -조건 : 질의응답을 선택했는가?
    -반응, 다음 상태: 선택했을 때만 질문 수를 보여준다.

    4. 내용 확인
    -행동, 이벤트 : 캐릭터명, 플레이 시간, 로그인 횟수 응답 내용을 읽고 '수정하기' 또는 '작성 완료하기' 를 클릭한다.
    -조건 : 수정인가, 완료인가?
    -반응, 다음 상태 : 수정하면 기본 값을 유지하고 조건 선택으로 돌아간다.
                    완료하면 완료 안내로 이동한다.

    5. 완료와 다시 설정
    -행동, 이벤트 : 완료 안내를 읽고 필요하면 '다시 작성하기'를 클릭한다.
    -반응, 다음상태 : 새 피드백의 캐릭터명, 플레이 시간, 로그인 횟수 응답, 진행 상태를 초기화하고 캐릭터명 입력부터 다시 시작한다.
                    이미 확인한 캐릭터 정보 수집 동의와 다른 기능을 유지한다.

# 5주차 사용자 행동에 반응하는 화면 만들기 기록

## 1. 사용자(user)가 무엇을 하는지
사전예약 폼에 이메일을 입력합니다.
## 2. 화면에서 무엇이 바뀌는지
사전예약 버튼 선택 후 버튼의 속성과 하단의 안내문구가 변경이 됩니다.
## 3. 어떤 코드로 연결했는지
고정되는 값은 const 제출 뒤 값을 변경하는 것은 let 을 사용합니다. 
is-success 성공상태 규칙을 만들어줍니다.
classList로 상태 스타일을 바꿉니다.
is-success로 웹페이지에서는 녹색 변경이 되지않았는데 화면사이즈가 768사이즈에서는 적용이 되었습니다.
#subscribeMessage, #subscribeMessage.is-success, #subscribeButton:disabled
상단 부분을 @media밖으로 보내서 화면크기가 768보다 클때도 적용되게 수정했습니다.

# 4주차 반응형 수정 기록

## 1. 확인한 문제
390px 작은 화면에서 메뉴, 기능 카드, 이메일 폼이 좁아 보였습니다.
이메일 폼은 손가락으로 선택할 수 있는 범위를 확보해야할 필요성이 있습니다.

## 2. 수정한 내용
- viewport 메타 태그를 추가했습니다.
- 콘텐츠에 width와 max-width를 함께 사용했습니다.
- 기능 카드 목록을 반응형 Grid로 변경하여 카드 수량이 늘었을때 1열에 맞게 세워지도록 합니다.
- 768px 이하에서 메뉴, 카드, 폼을 한 열로 구성했습니다.

## 3. 달라진 점
- 기본 페이지에서 너비를 줄였을때 확대하지 않아도 내용을 읽을 수 있습니다.
- 가로로 스크롤이 길어지는 이슈를 세로로 깔끔하게 볼 수 있도록 했습니다.

## 4. 확인할 화면 너비
1100px / 769px / 768px / 390px
